# TDD を 1 サイクル進める

`TODO.md` の **最初の未チェックの項目（`- [ ]`）を 1 つだけ** 選び、次の順に進める。ほかの項目には手を付けない。

## 1. Red

- その項目を確かめるテストを **1 つだけ** `tests/test_todo.sh` に追加する
- `bash tests/test_todo.sh` を実行し、追加したテストが **期待どおりの理由で** 失敗することを確かめる
- 失敗の出力（`FAIL - ...` の行と、その下の期待値・実際の値）を報告に含める
- 失敗しなかったら、まずテストの書き方を見直す。テストが正しく、振る舞いがすでに満たされている（最初から成功する）場合は、次のようにして、Green と Refactor は飛ばす
  1. 実装を一時的に壊して（例: 計算の式を変える）、追加したテストが失敗することを確かめる（テストのテスト）。その失敗の出力も報告に含める
  2. 実装を元に戻し、すべてのテストが成功することを確かめる。`git status --short -- todo.sh` で、`todo.sh` に変更が残っていないことも確かめる（何か表示されたら、元に戻しきれていないので直す）
  3. 「コミットの前に確かめること」を行い、テストの追加だけを `test:` としてコミットする。そのあと「4. 報告して止まる」に進む

## 2. Green

- テストが通る **最小限** のコードを `todo.sh` に書く。決まった値を返すだけの仮実装でもよい
- `bash tests/test_todo.sh` を実行し、**すべての** テストが通ることを確かめる
- 「コミットの前に確かめること」を行い、テストと実装を **振る舞いの変更** として `feat:` または `fix:` でコミットする

## 3. Refactor

- テストが通る状態を保ったまま、重複や分かりにくい名前を整える。必要がなければ何もしない
- 整えたら、「コミットの前に確かめること」を行い、**構造の変更** だけを `refactor:` として、Green とは別にコミットする

## コミットの前に確かめること

- `TODO.md` のその項目を `- [x]` にする（Green のコミット、または `test:` のコミットに含める）。作業中に気づいたことは、新しい項目として `TODO.md` に追加する
- `bash tests/test_todo.sh` と `shellcheck todo.sh tests/test_todo.sh` を実行し、どちらも成功することを確かめる

## 4. 報告して止まる

次のことを短く報告し、次の指示を待つ。

- 選んだ項目
- Red の結果（失敗したテストの名前と、失敗の理由。最初から成功した場合は、そのことと、実装を壊して確かめた結果）
- Green で書いたコードの要点（仮実装なら、そう書く）
- Refactor でしたこと
- 追加した TODO の項目と、作ったコミット

## してはいけないこと

- 一度に複数の項目を進める
- テストを消す・弱める・期待値を実際の出力に合わせて書き換える
- 頼まれていない機能を追加する
