# テストリスト（TODO.md）を作る

対象: $ARGUMENTS

1. 対象が Issue 番号なら `gh issue view <番号>` で内容を読む。仕様の説明なら、それを仕様とする
2. `todo.sh` と `tests/test_todo.sh` を読み、今の振る舞いとテストの書き方を確かめる
3. 期待される振る舞いを、テストにできる具体的な項目に分けて、リポジトリのルートの `TODO.md` に書く
   - 1 つの項目は「〜のとき、〜になる」のように、1 つのテストで確かめられる大きさにする
   - 簡単なもの（タスクが 0 件のとき、など）から順に並べる
   - 実装の方法（関数名や使うコマンド）は書かない
   - エラーの扱い、境界の値（0 件、最後の行に改行がない、など）、ヘルプの表示も項目にする
4. 次の書式で書く

   ```markdown
   # テストリスト: <機能の名前>（#<Issue 番号>）

   - [ ] 項目 1
   - [ ] 項目 2

   ## メモ

   - TDD の対象ではないこと、あとで考えること
   ```

5. コードとテストは **まだ書かない**。`TODO.md` を書いたら項目の一覧を見せ、追加・削除したい項目がないかを確認して止まる
