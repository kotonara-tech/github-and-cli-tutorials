# 発展編 第 3 章: モデルと effort の選び方

Claude Code では、作業に使う **モデル**（Claude の種類）と、Claude がどれだけ深く考えるかを決める **effort**（努力の度合い）を選べます。
この章では、それぞれの違いと、作業に合わせた選び方を学びます。

> [!NOTE]
> モデルの種類と名前は、2026 年 10 月時点のものです。新しいモデルは定期的に公開されます。最新の情報は [公式ドキュメント: モデルの設定](https://code.claude.com/docs/ja/model-config) を確認してください。

## この章のゴール

- [ ] モデルと effort の違いを説明できる
- [ ] `/model` と `/effort` で、モデルと effort を切り替えられる
- [ ] 作業の内容に合わせて、モデルと effort を選べる

**所要時間の目安:** 30〜45 分

## A3.1 モデルと effort の違い

Anthropic の Claude Code チームは、2 つの設定を次のように説明しています（[記事: Choosing a Claude model and effort level in Claude Code](https://claude.com/resources/articles/claude-model-and-effort-level-in-claude-code)）。

- **モデル** は、だいたい「**どれだけ賢いか**」を決める
- **effort** は、だいたい「**どれだけ念入りに取り組むか**」を決める

大きなモデルや高い effort ほど、難しい問題に強くなりますが、時間がかかり、利用上限（[第 1 章](01-setup.md#a12-必要なプランと費用)）を多く消費します。
**いつも最大にすればよいわけではありません。**

## A3.2 モデルの種類

Claude Code では、モデルを **エイリアス**（別名）で指定します。エイリアスを使うと、新しいバージョンが出たときに自動で最新のものに切り替わります。

| エイリアス | モデル（2026 年 10 月時点） | 向いている作業 |
| --- | --- | --- |
| `opus` | Claude Opus 5.5 | 複雑な推論が必要な作業。Pro / Max プランの **既定のモデル** |
| `sonnet` | Claude Sonnet 5.5 | 日常的なコーディング |
| `haiku` | Claude Haiku 5.5 | 簡単な作業。速くて、利用上限の消費が少ない |
| `fable` | Claude Fable 5.1 | 最も難しく、長い時間がかかる作業。プランによっては追加の料金（利用クレジット）がかかる |
| `opusplan` | plan モードでは Opus、実行では Sonnet | 計画は賢いモデルで立て、実装は日常向けのモデルで行う |
| `default` | アカウントの既定のモデルに戻す | 設定を元に戻したいとき |

## A3.3 モデルを切り替える

### Claude Code の中で切り替える

```text
/model
```

モデルの一覧が表示されるので、矢印キーで選んで <kbd>Enter</kbd> を押します。選んだモデルは、次回以降の会話の既定にもなります。
今の会話だけで使いたいときは、<kbd>Enter</kbd> の代わりに <kbd>s</kbd> を押します。

エイリアスを直接指定することもできます。

```text
/model sonnet
```

### 起動するときに指定する

```bash
claude --model sonnet
```

この場合、その会話だけがそのモデルになります。

## A3.4 effort を選ぶ

effort には 5 つのレベルがあります。Opus 5.5、Sonnet 5.5、Haiku 5.5 の既定は `medium` です。公式ドキュメントでは、次のように使い分けを説明しています。

| レベル | 向いている作業 |
| --- | --- |
| `low` | アイデア出し、名前の変更のような小さな変更など、結果を 1 つずつ確認する素早いやり取り |
| `medium` | 新しい機能の実装など、範囲がはっきりした日常的な作業（5.5 系のモデルの既定） |
| `high` | 既存のコードのバグ修正など、確認が大切な作業や、例外的な場合が起きやすい作業 |
| `xhigh` | より多く考えて、より深く推論する |
| `max` | 人が関わらずに取り組ませたい、とても難しい問題。考えすぎることもあるので、普段使いはしない |

### effort を切り替える

```text
/effort high
```

`/effort` だけを実行すると、スライダーが表示され、矢印キーで選べます。起動するときに `claude --effort high` のように指定することもできます。
`/effort` で選んだレベルは、次回以降の既定としても保存されます。保存したレベルを消して、モデルの既定（5.5 系なら `medium`）に戻すには、`/effort auto` を実行します。

### 1 回だけ深く考えてほしいとき

指示の中に `ultrathink` という言葉を入れると、effort の設定を変えずに、その 1 回だけより深く考えてもらえます。

```text
ultrathink この不具合の原因として考えられるものを、可能性の高い順に挙げてください。
```

「よく考えて」「think hard」などの言葉は特別な意味を持たず、普通の文章として扱われます。

## A3.5 作業に合わせて選ぶ

先ほどの記事では、選び方の基本を次のようにまとめています。

1. **まずは既定のまま使う。** ほとんどの作業は、モデルの既定の effort で十分です。作業ごとに細かく変える必要はありません。
2. **必要な情報を渡し、Claude もきちんと取り組んだのに間違えた** ときは、より賢い（大きな）モデルに切り替えます。
3. **ファイルを読まなかった、テストを実行しなかった** など、確認を飛ばして間違えたときは、effort を上げます。
4. **決まりきった作業** は、小さなモデルで十分です。

この発展編での目安です。

| 作業 | モデル | effort |
| --- | --- | --- |
| コードについて質問する、調べてもらう | 既定（`opus`）または `sonnet` | 既定 |
| plan モードで計画を立てる（[第 5 章](05-harness.md)） | 既定（`opus`） | 既定。広い範囲の計画なら `high` |
| TDD の 1 サイクルを回す（[第 6 章](06-tdd.md)） | 既定（`opus`）または `sonnet` | 既定 |
| 名前の変更、コメントの修正などの小さな作業 | `sonnet` または `haiku` | `low` |
| 原因が分からない不具合を調べる | 既定（`opus`） | `high` |
| テストのレビュー（[第 4 章](04-skills-and-agents.md) の subagent） | `sonnet` | 既定 |

> [!TIP]
> skill や subagent（[第 4 章](04-skills-and-agents.md)）のファイルには、`model` と `effort` を書けます。
> 「レビューは `sonnet` で」のように、役割ごとに決めておくと、毎回切り替える必要がありません。

## A3.6 利用上限を意識する

- `/usage` で、今の利用状況と、利用上限までの残りを確認できます。
- 大きなモデル、高い effort、長い会話ほど多く消費します。1 つの作業が終わったら `/clear` で会話を区切ると、無駄な消費を減らせます。
- Opus のモデルを速く動かす **fast モード**（`/fast`）もありますが、研究段階の機能（リサーチプレビュー）で、追加の料金がかかります。この教材では使いません（[公式ドキュメント: fast モード](https://code.claude.com/docs/ja/fast-mode)）。

## 演習

### 演習 A3-1: モデルと effort を確認する

Claude Code の中で `/status` を実行し、今使っているモデルを確認しましょう。続けて `/effort` を実行し、今の effort のレベルを確認します（<kbd>Esc</kbd> で閉じます）。

### 演習 A3-2: effort を変えて比べる

1. `/effort low` を実行してから、次のように聞きます。

   ```text
   @tests/test_todo.sh のテストで、足りないと思うケースを 3 つ挙げてください。
   ```

2. `/clear` で会話をリセットし、`/effort high` を実行してから、同じ質問をします。
3. 答えが返ってくるまでの時間と、答えの内容を比べましょう。終わったら `/effort auto` を実行して、既定に戻します。

<details>
<summary>解答例</summary>

一般的に、`high` のほうが時間をかけてファイルをよく読み、理由を添えた答えを返します。`low` は速く、要点だけの答えになることが多いです。
どちらがよいかは作業によって違います。「確認が大切な作業では effort を上げる」という目安を、実際の答えで確かめてみてください。

</details>

### 演習 A3-3: 小さな作業を小さなモデルで行う

`/model haiku` に切り替えて、次のような小さな作業を頼みます。変更を差分で確認したら、変更を破棄（または `git restore`）して元に戻し、`/model default` で既定のモデルに戻します。

```text
@todo.sh の usage 関数の説明文で、分かりにくい言葉があれば 1 つだけ直してください。
```

## まとめ

- モデルは「どれだけ賢いか」、effort は「どれだけ念入りに取り組むか」を決める
- `/model` と `/effort` で切り替える。`ultrathink` で 1 回だけ深く考えてもらえる
- まずは既定のまま使い、間違え方を見て、モデルを大きくするか effort を上げるかを決める
- 大きなモデルと高い effort は、利用上限を多く消費する
